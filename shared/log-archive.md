# 专项经验：日志归档

## 概述

本文档记录日志归档的经验教训，避免未来重复犯错。
由 Tech agent 创建，Main agent 补充维护。

---

## 归档目录规则

### 目录结构

```
1-Tech-Memory/
├── daily/                      ← 每日日志（只保留近期，如当月）
└── archive/
    ├── 说明.txt
    ├── YYYY-MM.md              ← 月度合并归档
    └── history-YYYY-MM/        ← 原始文件存档
        ├── YYYY-MM-DD.md
        └── ...
```

### 核心规则

1. **归档目录**：`1-Tech-Memory/archive/`，**不是** `daily/archive/`
2. **daily/ 只放近期日志**，按月归档到 archive/
3. **原始文件保留**：移动到 `archive/history-YYYY-MM/` 目录，**不删除**
4. **合并归档**：同月份文件合并为单个 `YYYY-MM.md`

## 归档操作流程

### 1. 准备阶段

```bash
# 确认待归档文件
ls /home/obsidian_vault/1-Tech-Memory/daily/YYYY-MM-*.md

# 创建归档目录
mkdir -p /home/obsidian_vault/1-Tech-Memory/archive/history-YYYY-MM
```

### 2. 复制原始文件到 history/

```bash
cp /home/obsidian_vault/1-Tech-Memory/daily/YYYY-MM-*.md \
   /home/obsidian_vault/1-Tech-Memory/archive/history-YYYY-MM/
```

### 3. 生成合并归档文件

使用 Python 脚本合并，关键逻辑：

```python
# 去掉 frontmatter（第一个 --- 到第二个 --- 之间的内容）
# 跳过一级标题（如 # 2026-03-26 - Daily Log）
# 保留 ## 和 ### 时段标题及正文内容
```

**注意**：必须用 Python 处理，shell 的 sed/awk 容易出错（特别是中文内容和多行 frontmatter）。

### 4. 验证完整性

```python
# 检查每个原始文件的关键时段标题是否都出现在归档中
import re
src_headers = set(re.findall(r'^#{1,3} .+', src_content, re.MULTILINE))
arch_headers = set(re.findall(r'^#{1,3} .+', archive_content, re.MULTILINE))
missing = src_headers - arch_headers
```

### 5. 清理 daily/ 下的已归档文件

```bash
rm /home/obsidian_vault/1-Tech-Memory/daily/YYYY-MM-*.md
```

## 标题层级规范

### 标准层级

| 层级 | 格式 | 说明 |
|------|------|------|
| 一级 `#` | `# 2026-03 月度归档` | 整个归档文档的总标题 |
| 二级 `##` | `## [2026-03-26]` | 日期标题，每天一个 |
| 三级 `###` | `### 09:13 AM - 自我介绍查询` | 时间条目，每天内的具体记录 |

### 处理原则

- 原始 daily 文件中的一级标题（如 `# 2026-03-26 - Daily Log`）在归档中需降为三级
- 原始文件中的二级标题（如 `## 09:13 AM - xxx`）在归档中需降为三级
- 日期标记（如 `## [2026-03-26]`）统一作为二级标题，放在每天内容的**开头**

## 踩坑记录

### 坑1：shell sed 处理 frontmatter 丢内容

**问题**：用 `sed '/^---$/,/^---$/d'` 删除 frontmatter 时，如果正文中也包含 `---` 分隔符，会导致内容被错误删除。

**解决方案**：用 Python 精确匹配第一个 `---` 到第二个 `---` 之间的内容。

### 坑2：awk 过滤一级标题时误删内容

**问题**：`awk '/^# /d'` 会删除所有以 `# ` 开头的行，包括某些文件中的二级标题（如果格式不规范）。

**解决方案**：用 Python 精确匹配 `line.startswith('# ') and not line.startswith('## ')`。

### 坑3：归档目录放错位置

**问题**：错误地创建 `daily/archive/` 目录，归档文件和原始日志混在一起。

**解决方案**：归档目录必须是 `1-Tech-Memory/archive/`，和 `daily/` 平级。

### 坑4：直接删除原始文件

**问题**：归档后直接删除 daily/ 下的原始文件，没有保留副本。

**解决方案**：原始文件必须移动到 `archive/history-YYYY-MM/` 目录保留，**不删除**。

### 坑5：日期标题位置搞反

**问题**：归档脚本将每天末尾的日期标记（如 `## [2026-03-26] 补充记录`）保留在内容块的末尾，导致归档文件中日期标题出现在每天内容的结尾而不是开头。

**根本原因**：原始 daily 文件中，日期标记是作为"补充记录"追加在文件末尾的，不是作为当天的开头标题。归档时需要识别并移到开头。

**解决方案**：在 Python 合并脚本中，先识别每天内容块末尾的日期标记，将其剥离并移到该内容块的开头。

### 坑6：标题层级不规范

**问题**：归档后时间条目（如 `## 09:13 AM - 自我介绍查询`）使用二级标题，与日期标题同级，层级混乱。

**正确层级**：
- 一级标题 `#`：月度归档总标题（如 `# 2026-03 月度归档`）
- 二级标题 `##`：日期标题（如 `## [2026-03-26]`）
- 三级标题 `###`：时间条目（如 `### 09:13 AM - 自我介绍查询`）

**解决方案**：合并脚本中需要降标题层级，将原始的 `## HH:MM` 改为 `### HH:MM`，原始文件中残留的一级标题也需降为三级。

### 坑7：Python 脚本修复引入新问题

**问题**：修复日期标题位置时，脚本多加了一个 `#`，把时间条目从 `##` 变成了 `# ##`（相当于四级标题），需要再次修复。

**根本原因**：修复脚本一次修改了多个维度（位置 + 层级），难以一次性验证正确性。

**解决方案**：
- 每次脚本只改一个维度
- 改完后立即验证，再改下一个维度
- 写成独立的脚本文件执行，便于回滚和对比

### 坑8：逐文件 shell 循环拼接不可靠

**问题**：在 shell for 循环中调用 python 单行脚本处理中文内容时，引号嵌套和转义导致脚本执行失败。

**解决方案**：写成完整的 Python 脚本文件执行，避免 shell 引号嵌套。

## 经验教训

1. **归档目录和 daily/ 目录必须分离** — 归档是 archive/，日志是 daily/
2. **原始文件必须保留** — 移动到 history/ 目录，不删除
3. **用 Python 处理文本** — 比 shell sed/awk 更可靠，特别是中文内容
4. **归档后必须验证** — 检查关键时段标题是否完整
5. **先复制再删除** — 确保归档完整后再清理源文件
6. **日期标题位置** — 日期标记（如 `## [2026-03-26]`）必须放在每天内容的**开头**，不是结尾
7. **标题层级规范** — 归档文件统一为：一级=月度标题、二级=日期标题、三级=时间条目，原始文件中不符合此层级的标题需降级
8. **Python 脚本修复需谨慎** — 每次只改一个维度（如只改位置或只改层级），避免一次修改引入多个问题导致难以排查
