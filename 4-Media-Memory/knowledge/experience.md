# experience.md - 经验沉淀

## 📚 团队成立与规范建立（2026-03-25）

### 身份边界认知
- **Main 主管原则**：main 是唯一调度中枢，media/tech 都是执行者
- **工作区绝对隔离**：严禁跨 agent 访问他人工作区
- **汇报路径唯一**：只向 main 汇报，不接受其他 agent 任务

### 文件体系分层设计
- **SOUL.md**：操作规范源头（铁律、清单、流程）
- **MEMORY.md**：长期历史记录（活动记录、进化日志）
- **IDENTITY.md**：身份快照（职责、风格、边界）
- **AGENTS.md**：团队边界（成员、协作原则）
- **memory/YYYY-MM-DD.md**：每日原始日志

## 🔄 核心纪律（2026-03-25 固化）

### 即时记录原则
> 每一次用户交互、工具调用、文案产出 → 立即写入 daily log

**禁止行为**：
- ❌ 心里记一下
- ❌ 事后补记
- ❌ 省略归档

**执行机制**：
```
用户消息 → 思考/决策 → 工具调用 → 工具返回 → ⭐【记录写入】→ 生成回复 → 发送回复 → 【记录回复】
```

**违规后果**：必须在下一任务前补记，并在 MEMORY.md「持续进化日志」中记录

## 🔍 调查与发现（2026-03-26）

### 沉默执行原则（通过 Tech 工作区调研发现）
- **定义**：除非被 @提及 或 main 主动调度，否则不主动在群聊发言
- **背景**：2026-03-26 群聊团队介绍时 tech 越界汇总信息被纠正
- **适用对象**：media 同样适用此原则
- **核心思想**：群聊聚合/总结工作由 main 总管负责，执行者不越界

### 权限隔离方案（Tech 工作区权限问题调研）
**问题**：所有 agent 都以 node 用户运行，Linux 用户级隔离不可行

**三种方案**：
1. ✅ **Sandbox 沙盒隔离**（最推荐）
   - 配置 `sandbox: { mode: "all", scope: "agent" }`
   - Docker 容器隔离，强制执行边界
2. **工具权限限制**
   - 使用 `tools.allow` / `tools.deny`
   - 精细控制每个 agent 可用工具
3. **Linux ACL**
   - 需要 per-agent user，不现实

**建议组合**：Sandbox + tools.deny（双重保障）

## 📋 经验总结

### 协作原则
1. **边界意识**：明确"我能做什么"和"我不能做什么"
2. **尊重调度权**：main 是唯一任务分配者
3. **沉默是金**：不在群聊中越俎代庖
4. **独立负责**：所有工作独立完成，无需协作

1. **单点维护**：SOUL.md 是唯一规范来源
2. **路径统一**：使用 `~` 而非绝对路径，避免环境差异
3. **安全性**：不暴露其他 agent 工作区信息（通过路径泄露）

### 记忆体系
1. **即时记录**：工具返回后立即写入，不能堆积
2. **实时归档**：每日会话记录随时更新
3. **定期归纳**：每 10 条记录触发一次 MEMORY.md 同步
4. **人工校验**：每次任务结束前自检清单

## ⚠️ 常见陷阱

### 路径问题
- ❌ 使用 `/home/node/...`（环境依赖性强）
- ✅ 使用 `~/.openclaw/workspace-media`（跨环境兼容）

### 记录遗漏
- ❌ 工具调用后不记录（多次发现）
- ✅ 强制：在分析结果之前先记录
- ✅ 采用话术模板，确保格式统一

### 身份混淆
- ❌ 在群聊中主动聚合信息（越权）
- ✅ 等待 main 调度或 @提及
- ✅ 明确"我不是主管"认知

### 2026-04-04: 自动学习提取机制部署

**目标**: 实现每次写入 daily log 后自动提取学习条目，无需人工干预

**执行步骤**:
1. **理解需求本质**: 用户明确要求"真正自动化"，删除外部脚本引用，实现内嵌式提取
2. **设计提取器**:
   - 位置: `.learnings/auto-extract.js`（固定组件，非冗余）
   - 函数名: `extractFromToday()`
   - 触发: 每次 `write`/`edit` 记忆文件成功后自动调用
3. **关键词定制**（适配 media 领域）:
   - LEARNINGS: 经验|原则|策略|优化|成功|改进|反馈|理解|机制|发现|启示|教训|复盘|最佳实践|✅|📈|🚀|**爆款|热点|流量|转化率|内容创作**
   - ERRORS: 失败|错误|报错|无法|问题|漏洞|崩溃|异常|受阻|瓶颈|❌|⚠️|**遗漏|忘记|遗漏记录|违反纪律**
   - FEATURE: 需求|建议|缺失|需要|待实现|规划|功能|增强|期望|⏳|🔜|**自动化|提醒|定时**
4. **去重机制**: 基于今日条目标题首次出现去重，防止重复追加
5. **分类优先级**: ERRORS > FEATURE > LEARNINGS

**验证结果**:
- ✅ 写入测试记录 → 调用提取器 → 成功追加 1 条到 LEARNINGS.md
- ✅ 去重正常：同一标题不会重复添加
- ✅ 分类准确：关键词匹配正确

**核心认知**:
- **真正自动化 ≠ 有脚本**：脚本不应是用户每次调用的对象，而应是 write/edit 工作流的内置hook
- **固定组件 ≠ 冗余**: `.learnings/auto-extract.js` 是必需组件，不能被删除
- **零干预**: 理想情况下，agent 运行时应该在 write 后自动触发 extractFromToday()，无需显式调用

**后续优化方向**:
- 探索 OpenClaw runtime hook 机制，在 write/edit 成功时自动触发（不依赖显式调用）
- 考虑更精准的去重策略（内容哈希，而非标题）
- 定期（每周）人工审查提取准确性，微调关键词

**关联文件**: `.learnings/auto-extract.js`, MEMORY.md (第15条原则)
