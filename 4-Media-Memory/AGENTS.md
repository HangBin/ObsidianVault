## 🔚 对话结束协议（最高优先级）

**每次回复用户之前，必须执行以下步骤，不可跳过：**

1. **检查今天的记忆文件是否存在**
   - 工作区路径: `memory/YYYY-MM-DD.md`
   - Obsidian路径: `/home/obsidian_vault/4-Media-Memory/daily/YYYY-MM-DD.md`
   - 不存在 → 创建并写入标准 frontmatter + 文件头：
     ```yaml
     ---
     date: YYYY-MM-DD
     weekday: <星期几>
     tags:
       - daily-log
       - media-agent
     created: YYYY-MM-DDTHH:MM:SS+08:00
     modified: YYYY-MM-DDTHH:MM:SS+08:00
     ---
     ```
     然后写入 `# YYYY-MM-DD 日志` 标题
   - 已存在 → 检查 frontmatter 是否完整（必须有 created/modified/tags），缺失则补全
   - ⚠️ **frontmatter 是源头**：同步脚本不会重新生成 frontmatter，源文件有什么就传什么

2. **合并当天所有子记忆文件**
   - 扫描 `memory/YYYY-MM-DD*.md`（排除主文件本身）
   - **去重检查**：对比子文件内容是否已在主文件中存在（心跳子文件经常重复）
     - 已存在 → 直接删除子文件，不重复写入
     - 不存在 → 将新内容按时间顺序融入主文件对应位置
   - 同步合并到 Obsidian `daily/YYYY-MM-DD.md`
   - 合并完成后**立即删除子文件**，不留残留碎片
   - ⚠️ 不加任何分隔标记，直接按时间顺序融入对应记录
   - ⚠️ 心跳产生的子文件通常是重复记录，重点检查是否已存在于主文件
   - 🔴 **合并完成 = 立即执行第4步清理旧日期文件**，不可停在"子文件删了"这一步

3. **⚠️ 当天文件完整性检查（每次写入新记忆前必须执行，顺序优先）**
   - **🔴 在写入任何新记忆之前，必须先执行本步骤**
   - 检查方法：
     1. 调用 `sessions_list(activeMinutes=720)` 获取当天所有活跃 session
     2. 对每个 session 调用 `sessions_history`，提取所有用户消息的时间戳
     3. 对比 `memory/YYYY-MM-DD.md` 中已记录的时间点
     4. 发现遗漏 → 立即补写（格式：`## HH:MM - [主题] / 触发 / 工具 / 结果 / 决策`）
     5. 无法推断主题时简写：`## HH:MM - 对话记录（来源：session补录）`
   - ⚠️ **先检查完整性 → 再写入新记忆 → 再清理旧文件**，这个顺序不可颠倒
   - 🔴 **不存在"我刚才已经写了"的心理跳过！** 每次写入前都必须重新检查

4. **⚠️ 其他日期文件检查（每次记忆写入时执行）**
   - 扫描 `memory/` 下除当天之外的所有 `2026-*.md` 文件（**包含昨天、前天、更早的所有文件**）
   - **🔴 创建当天文件前必做**：先执行本步骤检查+清理，再创建当天文件。顺序不可颠倒
   - 对每个文件按以下 Checklist 逐项执行（不可跳过任何一项）：
     - [ ] **Obsidian同步**：`md5sum memory/YYYY-MM-DD.md /home/obsidian_vault/4-Media-Memory/daily/YYYY-MM-DD.md` → 不一致则用 `cp` 同步
     - [ ] **🔴 冗余清理（原子操作）**：md5一致 → **立即执行 `rm memory/YYYY-MM-DD.md`**。md5对比 + rm 删除是一个不可分割的整体，不允许只检查不删除。"检查通过"只是删除的前提，不是终点。"检查了但没删除"= 没做
     - [ ] **冗余子文件**：检查是否存在 `YYYY-MM-DD-*.md` 子文件 → 有则合并到主文件后立即删除
   - ⚠️ 昨天、前天的工作区文件只要 Obsidian 已同步完整，一律删除，不留冗余
   - ⚠️ **工作区只允许保留当天的 memory 文件**，其他一律删除
   - 🔴 **不存在"正常的跳过"！** 同步完整=删除，这是唯一正确的处理方式

   **违规记录：**
   - 2026-06-08：工作区 2026-06-08.md 与 Obsidian 版本 md5 不一致（缺少闲鱼自动化能力调研章节），已修复同步

5. **追加本次对话记录**
   - ⚠️ **时间顺序规则（最高优先级）**：新记录必须追加到文件**末尾**，按时间从上到下排列。禁止在已有记录前面插入，禁止打乱时间顺序。
   - ⚠️ **写入前检查**：追加前必须先 `read` 文件末尾，确认最后一条记录的时间早于当前记录时间。如果发现时间顺序错乱，立即重写整个文件恢复正确顺序。
   - 格式:
   ```markdown
   ## HH:MM - [主题]
   **触发**: 用户说了什么 / 内部触发
   **工具**: 调用了哪些工具（无则写"无"）
   **结果**: 成功/失败 + 关键产出
   **决策**: 为什么这样做
   ```

6. **双写确认**
   - 写入 `memory/YYYY-MM-DD.md`（工作区本地）
   - 写入 `/home/obsidian_vault/4-Media-Memory/daily/YYYY-MM-DD.md`（Obsidian vault）
   - **同步更新索引**：如果本次操作涉及 daily/ 目录的文件变动（新增/修改/删除日志文件），必须同步更新 `/home/obsidian_vault/4-Media-Memory/daily/daily-index.md`
   - 如果 Obsidian 不可写，只写本地，标记"待同步到 Obsidian"

7. **如果涉及重要决策/新知识/新经验 → 同步更新 MEMORY.md（Obsidian版 `/home/obsidian_vault/4-Media-Memory/MEMORY.md`）**

8. **回复用户**

⚠️ **防跳过铁律**：
- 无论对话内容是什么、无论调用了多少工具、无论是否已经在操作文件
- 在发出任何面向用户的回复之前，必须逐字过一遍本协议的步骤编号 1→8
- 如果正在执行某项工具调用（edit/exec/write），在工具返回结果后、回复用户之前，必须重新确认所有步骤已完成
- 绝对不允许"我刚才已经做了"的心理跳过——每一步都必须有明确的执行证据（工具调用记录）
- 违规 = 对话结束协议未执行 = 最高优先级违规，等同于身份认知违规

⚠️ 此步骤不可跳过，即使对话内容看似"不重要"
⚠️ 空对话（仅闲聊）可简写一行：`## HH:MM - 闲聊，无重要操作`

### 写入规则
- **对话结束即记录**：每次对话结束前按「🔚 对话结束协议」自动写入，替代旧的被动记录方式
- **定期归档**：当日日志同步到 Obsidian `daily/`（通过对话结束协议双写机制自动完成）
- **经验提炼**：标记 `💡 关键教训`、`🚨 问题根因`、`✅ 成果` 的条目 → 提炼到 `knowledge/` 和 `MEMORY.md`
- **定期整理**：每 10 条记录或每 10 分钟 → 归纳爆款标题、文案模板、热点方向 → 同步到 MEMORY.md

### 只写文件，不做"心理记忆"

- 记忆容量有限，想保留就写入文件
- "心里记一下"会随会话重启消失，文件不会
- 当有人说"记住这个" → 立刻写入 `memory/YYYY-MM-DD.md`
- 学到可复用的方法 → 更新 AGENTS.md、TOOLS.md 或对应技能文档
- 出现错误 → 记录原因与修正，避免未来重复犯错
- 文件 > 脑子
