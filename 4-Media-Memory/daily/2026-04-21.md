assistant: 对您的专项浏览器自动化文档检索问题，我整理了清晰的操作指南：

1. **QMD集合配置验证**
```bash
# 查看当前QMD集合配置
qmd collection list

# 检查index.yml配置（推荐路径）
cat ~/.config/qmd/index.yml

# 推荐修正后的配置片段：
share:
  path: /root/.openclaw/share
  pattern: "**/*.md"
  context: "多代理共享文档集合"
```

2. **正确检索是使用share集合，而非browser集合**
```bash
# 假设experience-browser.md在共享目录中
qmd search "browser automation" -c share --max-results 5

# 若要专门索引browser目录，需：
qmd update browser  # 先更新索引
qmd search "CDP 9222" -c browser --max-results 3
```

3. **文件路径验证步骤**
```bash
# 验证文件实际路径
ls -la /root/.openclaw/share/browser/ | grep experience-browser.md

# 检查文件大小/最后修改时间
stat -c %s /root/.openclaw/share/browser/experience-browser.md
```

4. **检查索引状态**
```bash
# 查看索引状态
qmd status | grep "Pending"

# 构建向量索引（如果使用语义搜索）
qmd embed -c share
```

5. **完整搜索流程示例**
```bash
# 通用文本搜索（用关键词）
qmd search "browser performance metrics" -c share

# 向量语义搜索（需预先embedding）
qmd query "如何优化无头浏览器性能" -c share

# 查看文档预览
qmd read -c share "experience-browser.md" lines 1-20

# 列出所有匹配结果
qmd ls share | grep "browser"
```

**关键注意事项：**
1. 避免使用软链接，直接索引原始路径
2. 修改集合后必须执行`qmd update`重建索引
3. 通过`-c`参数严格指定集合名称
4. 如果文件未被索引，可能是路径配置问题
5. BM25检索速度快，向量检索更智能但需要embedding

如果操作后仍无法找到文档，请检查以下几点：
1. 文件是否真的存在（`ls -a`查看隐藏文件）
2. 敏感权限限制（检查权限设置）
3. 是否包含在集合的文件模式中（`pattern`字段）
4. 集合是否被启用（检查集合状态）
5. QMD版本是否支持所需功能（`qmd version`查看）

您可以通过`qmd status`详细查看索引状态，或用`qmd embed`重建向量索引。需要时我可帮您检查具体路径配置。
