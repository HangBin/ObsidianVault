## 13:29 - publish.py 报错修复

**触发**: 老板反馈 publish.py 运行报错
**工具**: exec、read、edit、Playwright 调试

### 问题诊断

**报错1：`Missing X server`**
- 原因：`headless=False` 在无头服务器上无法启动
- 修复：改为 `headless=True`

**报错2：页面加载超时（60秒无 input/contenteditable）**
- 原因1：`wait_until='networkidle'` 在闲鱼 SPA 上永远等不到
- 原因2：Cookie 未生效，页面显示"立即登录"
- 修复：改为 `wait_until='domcontentloaded'` + 增加等待时间到 8 秒

**报错3：Cookie 中缺少 `a1` 字段**
- `a1` 是闲鱼的 HttpOnly 核心登录凭证
- Cookie 中只有 21 个字段，缺少关键的 `a1`
- CDP 确认浏览器 session 中也没有 `a1`

### 根因分析（6月10日已确认）

1. **Cookie 缺少 `a1`** — HttpOnly cookie，代码注入无法设置
2. **服务器 IP 被闲鱼风控** — 机房 IP 被拦截（240e:36f:...）
3. 6月10日的截图也证实当时未登录（所有截图都是扫码登录页面）

### 代码修复

1. ✅ `headless=False` → `headless=True`
2. ✅ `wait_until='networkidle'` → `'domcontentloaded'`
3. ✅ 增加登录状态检测逻辑（检测"扫码安全登录"/"短信登录"/"立即登录"）
4. ✅ 增加文件上传控件检测（`input[type="file"]`）
5. ✅ 延长 SPA 渲染等待时间（5s → 8s）

## 19:00 - Cookie 提取攻坚 & 闲鱼发布脚本卡点分析

**触发**: 老板询问"昨天给的 cookies 还有什么问题"，要求解释为什么不能像小红书一样直接用 Cookie 发请求
**工具**: exec, read, tavily_search, browser_cookie3, jeepney D-Bus, ctypes libsecret

### 核心发现：小红书 vs 闲鱼 Cookie 机制差异

**小红书**：
- 用 `xhs-cli` 库，直接发 HTTP API 请求
- Cookie 中有 `a1`（用户标识）和 `web_session`（会话 ID）
- 不需要浏览器，纯 API 调用

**闲鱼**：
- 用 Playwright 打开浏览器访问 `goofish.com`
- `a1` 是 HttpOnly cookie，JavaScript 读不到，代码注入无法设置
- 即使注入 21 个 cookie，浏览器自己的 cookie jar 里没有 `a1`，闲鱼就不认
- 闲鱼发布接口需要 `x5sec` 签名（基于 `a1` + `x5secdata` + `x5sectag`）

### Cookie 提取尝试（全部失败）

1. ✅ `browser-cookie3` 提取到 21 个 cookie（但无 `a1`，因为 HttpOnly）
2. ❌ AES-GCM 解密（keyring 密码 `chrome` + PBKDF2）→ MAC check failed
3. ❌ AES-CBC 解密（全零 IV）→ padding error
4. ❌ jeepney D-Bus 获取 libsecret 密码 → SearchItems 返回 0（keyring 未注册到 D-Bus）
5. ❌ ctypes 调用 libsecret C API → schema 属性不匹配
6. ❌ secretstorage 库 → Prompt dismissed（无 GUI）

### 关键发现

- GNOME Keyring 中 Chrome Safe Storage 密码存储为 base64 编码的 16 字节二进制：`NVJu233CQnMsVK6FevBNEA==`
- 解密需要弹出密码提示框，服务器端无 GUI 无法交互
- 老板在 Windows Chrome 上已登录闲鱼，但 Network 面板的 Cookie 里也没有 `a1`（HttpOnly）
