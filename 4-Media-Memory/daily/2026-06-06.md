### 📖 学习要点总结

**1. GEP Evolver 架构**
- 核心流程：触发信号 → 基因匹配 → executor 执行修改 → 自动 solidify → 基因库更新
- 三层 scope 结构：main（通用58个基因）、final（财务专属56个）、tech（技术专属16个）
- selector 加载逻辑：当前 scope + main scope，按 ID 去重，当前 scope 优先

**2. 关键踩坑经验**
- **Solidify 环境变量缺一不可**：`OPENCLAW_WORKSPACE` + `EVOLVER_SESSION_SCOPE` 必须同时设置
- **自动 solidify 检测机制**：executor agent token 可能不够，evolve.sh 末尾必须有自动检测+自动 solidify 逻辑
- **信号降噪**：exec 工具的阈值从 5 提高到 20，避免 executor 自身正常操作触发自引用信号
- **基因去重**：同一基因可能以不同信号数重复出现，需保留更完整的版本
- **局部最优问题**：连续选同一基因说明信号或选择器有问题

**3. 基因注入规范（SOP）**
- 必须进入子文件夹深度扫描，禁止只看目录结构
- skills/ 下的 references/ 和 scripts/ 是核心经验源
- cron 脚本的 prompt 往往是最完整的操作规范
- 共享目录（share/）包含跨 agent 共同经验
- 违规记录是最好的 repair 基因来源
- 通用基因放 main scope，不要在各 scope 重复存放

**4. 基因格式规范**
- JSONL 格式，包含 type/id/category/signals_match/preconditions/strategy/constraints/validation
- signals_match 是关键词数组，用于匹配信号
- preconditions 定义适用条件
- strategy 是具体执行步骤
- constraints 限制文件范围和路径
- validation 定义验证标准

**5. 当前状态**
- Tech scope: 52 基因, 19 轮 cycle, 83% 成功率
- Final scope: 56 专属基因, 10 轮 cycle
- 下一步：定时触发、积累 capsule、蒸馏高阶基因

### 💡 关键教训
1. 环境变量是 solidify 的关键——两个缺一不可
2. executor 修改量要控制，聚焦核心代码
3. 基因选择要避免局部最优
4. 自动检测机制很重要——不能依赖 executor 自行完成 solidify
5. 知识源要持续扩充
6. 多 scope 环境变量各不相同
7. 通用基因必须放 main scope，不要重复存放
