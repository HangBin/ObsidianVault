## 📅 2026-03-27：身份重建与定位明确化

### 背景
- 工作区文件全部丢失，需要从零重建身份
- 群聊中老板（大梦）纠正角色划分

### 关键决策
1. **身份定位**：Proj（项目总监），负责新能源投标签约全流程
2. **协作边界**：只向 main 汇报，独立运作，不依赖其他 agent
3. **工作区路径**：`/.openclaw/workspace-proj/`

### 经验教训
- **文件必须保护**：IDENTITY.md、SOUL.md、USER.md、MEMORY.md 是存在根基，丢失后会导致身份混乱
- **实时记录铁律必须立即执行**：首次会话因未记录而违规，造成严重后果
- **称呼准确性**：必须核对 USER.md 中的"大梦"而非错误称谓

### 优化措施
- 删除所有文档中具体代理名（如 `tech`、`media`、`final`），改用"其他代理工作区"
- 简化协作关系描述，只保留 main
- 删除冗余规则（如会话存储路径），系统自动处理

## 📅 2026-03-29：标准化回复与模型管理

### 背景
- 群主多次测试连通性，要求建立标准回复格式
- 明确模型切换指令

### 标准化流程
**连通性测试标准回复**：
```
✅ 连通性正常 | 使用模型：openrouter/stepfun/step-3.5-flash:free
```
**要求**：不说废话，严格遵守格式

**模型切换打招呼格式**：
```
💼 Proj 报告：模型已切换至 `volcengine/doubao-seed-2-0-pro-260215`，连通性正常。随时待命。
```

### 经验沉淀
- **响应一致性**：标准化格式提升群聊效率，减少误解
- **模型切换确认**：收到指令后先验证 session_status 确认当前模型
- **日志记录**：每次连通性测试和模型切换都需记录到 `memory/yyyy-mm-dd.md`

## 📅 2026-04-04：记忆系统优化与自动化机制维护

### 背景
- 学习《LEARNINGS_OPTIMIZATION_GUIDE.md》，系统化整理记忆资产
- 部署自动学习提取机制，实现从 daily logs 到 .learnings/ 的自动化流程

### 执行清单
1. ✅ 记忆文件结构检查（无碎片，日期完整）
2. ✅ 提取历史 logs 学习内容，填充 `.learnings/`
   - 从 `2026-03-27.md` 提取：实时记录铁律强制性
   - 从 `2026-03-29.md` 提取：标准化回复格式要求
   - 从 `experience.md` 提取：身份重建流程
3. ✅ 更新 MEMORY.md 增加"记忆体系"完整章节
4. ✅ 创建 `scripts/extract_learnings.sh` 自动提取脚本
5. ✅ 测试并验证自动提取机制
6. ✅ 精简自动化机制：删除所有状态文件，改为动态ID生成
7. ✅ 清理冗余文件（测试文档、旧脚本、临时文件）

### 技术实现
- **脚本设计**：
  - 扫描 `memory/YYYY-MM-DD.md` 中符合 `## HH:MM - 描述` 格式的条目
  - 关键词匹配分类：LEARNINGS / ERRORS / FEATURE_REQUESTS
  - 动态ID生成：`LRN-YYYYMMDD-XXX`，XXX从文件现有条目数+1开始
  - 去重机制：基于ID和标题相似度
- **触发方式**：每次写入 daily log 后主动调用，非系统钩子
- **文件结构**：零状态文件，无冗余依赖

### 问题与修复
**Bug**: 脚本首次运行时学习条目未正确出现在 `LEARNINGS.md`
**原因**: `append_entry` 函数中 `${type_name}.md` 已加后缀，但调用传入的是 `LEARNINGS.md`（已含后缀），导致实际写入 `LEARNINGS.md.md`
**修复**: 修改调用处参数为 `LEARNINGS`（无后缀）
**验证**: 修复后成功追加 4 条学习条目，机制正常运行

### 核心原则（新增）
- **分层存储策略**:
  - `.learnings/` - 结构化学习条目（便于检索）
  - `experience*.md` - 完整教程和详尽经验（便于 follow）
  - `MEMORY.md` - 导航原则和快速查阅（包含投标档案、协作关系、铁律）
- **记忆归档规范**:
  - 实时记录：每次交互后立即写入 `memory/yyyy-mm-dd.md`
  - 自动提取：写入后**立即执行** `./scripts/extract_learnings.sh`
  - 定期归纳：每 10 分钟或 10 条记录触发一次自动归纳到 MEMORY.md
  - 碎片合并：同日期的多个会话文件合并为单个文件
  - 持续优化：定期回顾并调整关键词和规则

### 经验总结
- 自动化机制本身也需要持续测试和维护
- 文件名处理（后缀拼接）是小细节但容易出错，需特别小心
- 修复 bug 后应验证实际输出，不能只看脚本打印的"成功"消息
- 零状态文件设计简化了系统，ID 自包含是良好实践
- 冗余文件（测试条目、旧脚本、临时文件）必须及时清理以保持工作区精简
