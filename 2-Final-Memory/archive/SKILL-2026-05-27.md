## 🔴 报告逻辑一致性规则（最高优先级，2026-05-25 更新）

> 以下规则是为了防止报告内部出现矛盾的操作建议。每次生成报告前必须过一遍。

### 规则1：新基金推荐必须检查已持有持仓

**在推荐任何新基金之前，必须先检查portfolio.md中是否已持有同类型/同板块基金：**

1. 读取portfolio.md的完整持仓列表
2. 对每个推荐基金，检查是否已持有同一板块/同一主题的基金
3. **如果已持有同类型基金**：
   - 若该基金刚建仓（3天内）→ **禁止推荐同类型基金**，应在报告中明确说明"已持有XX，不重复推荐"
   - 若该基金已持有且表现正常 → **可以推荐同方向加仓**，但必须说明"已持有XX，可同方向加仓"
   - 若该基金已持有但短期承压 → **禁止推荐同类型基金**，应提示风险
4. **绝对禁止**：在提示某板块短期风险（如减持潮）的同时，又推荐同板块的新基金

### 规则2：风险提示与操作建议必须一致

**报告中不能出现以下矛盾：**

1. ❌ 在"风险提示"中说"半导体减持潮压制情绪"，又在"新推荐"中推荐半导体基金
2. ❌ 对刚建仓3天的基金给出"关注止损"建议（说明建仓时机判断有误，应反思而非止损）
3. ❌ 对已清仓的基金给出"继续持有"或"减仓"建议
4. ❌ 在"市场温度"中评分为"偏冷"，却在"操作建议"中大幅加仓

**正确做法：**
- 短期看空某板块 → 已持有的减仓锁利，不推荐同类型新基金
- 刚建仓的基金 → 给予观察期（至少5个交易日），不轻易止损
- 已清仓的基金 → 只能推荐"重新建仓"，不能给出持有/减仓建议

### 规则3：报告必须包含完整章节

**早盘报告必须包含以下13个章节，不可缺失：**

1. 🌡️ 市场温度（0-10分）
2. 🧭 市场风向（核心事件、行情核心逻辑）
3. 😤 投资情绪（积极/风险因素、资金面）
4. 📰 行业政策（重点政策方向、持仓关联）
5. 📊 昨日板块涨跌 + 资金流向（含融资融券/深股通/MSCI中国替代数据 + 前日连续性分析 + 期货异动）
6. 📋 持仓操作建议（逐只分析，按盈利区/浅亏区/新建仓区/贵金属/债券分类）
7. 🔗 持仓关联分析（高关联度持仓、板块受益分析）
8. 📈 今日指数预判区间（含走势模式检查、双向预案、基准/超预期情景）
9. 🎯 今日操作优先级（🔴必须/🟡建议/🟢可等三级）
10. 🆕 新基金建仓推荐（含推荐逻辑、已持有检查、API验证）
11. 📊 关键数据看板（四大指数+外围市场+持仓触发线）
12. ⚠️ 风险提示（市场风险+个股风险+流动性风险）
13. 📌 今日重点关注（事件时间表+极端行情预案）

### 规则4：新基金推荐逻辑必须自洽

**推荐新基金时，必须在报告中包含"推荐逻辑"段落：**

1. 说明预判当日资金流入哪些板块
2. 对每个预判板块，检查是否已持有同类型基金
3. 如果已持有 → 说明"已持有XX，不重复推荐"或"已持有XX，可同方向加仓"
4. 如果未持有 → 给出推荐基金+API验证
5. 绝对不能在提示某板块风险的同时推荐同板块基金

# A股每日四时段报告生成

## 执行流程总览

```
Step 0: 确定报告类型（早盘/午盘/尾盘/复盘）
Step 1: 数据采集（指数行情 + 资金流向 + 外围市场 + 资讯搜索）
Step 2: 读取上下文（前序报告 + portfolio.md + MEMORY.md）
Step 3: 生成报告（按对应模板结构输出）
Step 4: 保存报告（MD文件 → report/ 目录）
Step 5: 邮件发送（md_to_html.py → send_email_multi.py）
Step 6: 临时文件清理
```

> **超时处理**：单次 API 调用超30秒 → 切换备用源。搜索超20秒 → 换关键词。
> **核心原则**：所有市场数据必须通过 API 获取，禁止仅依赖搜索结果。资金流向每次必须重新调用。

## Step 0：确定报告类型

| 类型 | 生成时间 | 市场状态 | 核心目标 |
|------|---------|---------|---------|
| **早盘** | 09:10 | 盘前 | 预判全天走势 + 设定操作条件 |
| **午盘** | 12:15 | 午间休市 | 验证早盘预判 + 更新操作建议 |
| **尾盘** | 14:30 | 盘中 | 收盘前关键操作清单 + 止盈止损调整 |
| **复盘** | 16:00 | 收盘后 | 命中率评估 + 改进方案追踪 |

## Step 1：数据采集

### 1.0 并行采集（所有报告类型通用）

**所有报告**使用预置脚本并行采集，耗时从60-90秒降至约1秒：

```bash
SCRIPT=/root/.openclaw/workspace-final/skills/a-stock-daily-report/scripts/collect_report_data.py

# 早盘
python3 $SCRIPT --type morning --output /tmp/morning_data.json

# 午盘
python3 $SCRIPT --type afternoon --output /tmp/afternoon_data.json

# 尾盘
python3 $SCRIPT --type tail --output /tmp/tail_data.json

# 复盘
python3 $SCRIPT --type review --output /tmp/review_data.json
```

脚本并行采集（5线程）：
- 腾讯财经四大指数（GBK编码解析）
- 天天基金持仓估值（自动从portfolio.md提取持仓区代码，不含长期关注区）
- 外围市场数据（港股/美股/黄金/原油）
- 东方财富push2需单独通过 `web_fetch` 调用（服务器端拦截urllib/curl/requests）

脚本输出JSON到stdout，`--output` 参数可同时写入文件。JSON中包含 `web_fetch_required` 字段，列出需要单独通过 web_fetch 采集的数据项。

> ⚠️ 东方财富push2接口只能通过 OpenClaw 的 `web_fetch` 工具调用，urllib/curl/requests 均被服务器端关闭连接。

### 1.1 东方财富push2（每次必须重新调用！）

脚本标记为 `_needs_web_fetch` 的数据项，通过 `web_fetch` 单独采集：

```bash
# 概念板块资金流向TOP15
web_fetch "https://push2.eastmoney.com/api/qt/clist/get?pn=1&pz=15&po=1&np=1&fltt=2&invt=2&fid=f62&fs=m:90+t:3&fields=f2,f3,f4,f6,f12,f14,f62" maxChars=8000

# 行业板块外资流向TOP10
web_fetch "https://push2.eastmoney.com/api/qt/clist/get?pn=1&pz=10&po=1&np=1&fltt=2&invt=2&fid=f62&fs=m:90+t:2&fields=f2,f3,f4,f6,f12,f14,f62" maxChars=8000
```

### 1.2 资讯搜索

- 当日政策新闻、行业热点（Tavily搜索或百度千帆）
- 早盘/复盘需额外搜索外围市场资讯（美股期货/港股/A50）
- 前日资金流向连续性分析（读取前日复盘）

## Step 3：报告结构

详见 [references/report-templates.md](references/report-templates.md)，包含四种报告的完整模板。

核心要求：
- **数据标注来源**：每份数据标注 API 来源和时间
- **条件触发检查表**：午盘/尾盘必须逐一核对前序条件
- **量化区间**：预判必须给区间，禁止单点预测
- **分级操作清单**：尾盘必须分 🔴必须/🟡建议/🟢可等
- **双向预案**：连续两日相同走势后，第三日必须同时列出"延续"和"反转"两种情景，各50%
- **情绪校准**：市场温度评分前检查资金面+技术面+情绪面三者是否一致
- **尾盘双区间**：尾盘加速预判必须给出"保守"和"乐观"两个区间

### 3.1 分步生成（所有报告类型必须执行）

所有报告分3步生成，每步独立写入文件，避免截断：

#### 早盘报告（13章 → 分3步）
```
Step A: write 核心章节
  → 封面 + 市场温度 + 市场风向 + 投资情绪 + 行业政策

Step B: write 数据章节
  → 昨日板块涨跌+资金流向 + 持仓操作建议 + 持仓关联分析

Step C: write 辅助章节
  → 今日指数预判区间 + 操作优先级 + 新基金推荐 + 关键数据看板 + 风险提示 + 今日重点关注
```

#### 午盘报告（9章 → 分3步）
```
Step A: write 核心章节
  → 封面 + 早盘操作条件逐一检查 + 条件触发汇总

Step B: write 数据章节
  → 上午大盘表现 + 外资动向+资金流向 + 上午热点板块与持仓关联

Step C: write 辅助章节
  → 早盘要素变化对比 + 持仓表现+建议更新 + 新信号 + 午后操作决策树 + 新基金推荐更新 + 风险提示
```

#### 尾盘报告（9章 → 分3步）
```
Step A: write 核心章节
  → 封面 + 持仓操作指令表 + 条件触发汇总

Step B: append 数据章节
  → 今日大盘表现 + 外资动向专节 + 早盘要素变化对比 + 持仓表现速览

Step C: append 辅助章节
  → 新信号 + 尾盘加速预判+市场关注点 + 收盘前操作清单 + 新基金推荐 + 长期关注区
```

#### 复盘报告（11章 → 分3步）
```
Step A: write 核心章节
  → 封面 + 全天行情回顾 + 早盘分析评估 + 午盘分析评估

Step B: write 数据章节
  → 尾盘分析评估 + 命中率差异根因分析 + 改进方案执行效果追踪

Step C: write 辅助章节
  → 资金流向深度分析 + 新基金推荐效果追踪 + 新信号总结 + 触发条件更新 + 长期关注区评估 + 综合评分 + 经验教训
```

**关键规则**：
- Step A 用 `write` 工具（覆盖模式），确保文件从头开始
- Step B/C 用 `write` 工具（覆盖模式）写入临时文件，再用 `exec cat >>` 追加到主文件
- 或者 Step A 用 `write`，Step B/C 用 `exec cat >>` 直接追加
- 每步写入后检查文件行数，确认无截断
- 东方财富push2数据在Step B中通过 `web_fetch` 单独调用

## Step 5：邮件发送

详见 [references/email-guide.md](references/email-guide.md)。

**强制流程**：
1. MD报告 → 保存到 report/ 目录
2. `python3 /root/.openclaw/share/send-email/md_to_html.py <input.md> /tmp/<output.html> "标题" "报告类型"`
3. **排版验证**：`<pre>` 必须为 0
4. `python3 /root/.openclaw/share/send-email/send_email_multi.py --group all --subject "标题" --html-file /tmp/<output.html>`
5. **清理 `/tmp/` 临时文件**

**禁止**：直接发纯文本、复制旧 HTML、跳过排版验证。
