## 12:07 - 学习共享目录 browser 组件

**用户指令**: "你学习下共享目录的：/.openclaw/share/browser组件"

**学习内容**:
1. **根目录文件结构**:
   - `INSTALL.md` - 完整安装与使用指南
   - `experience-browser.md` - 技术根因分析与最佳实践
   - `agent-browser.env` - 环境变量配置
   - `browser-stable.sh` - 推荐控制脚本（封装 agent-browser batch）
   - `chromium-cdp.service` - systemd 服务定义
   - `docs/` - 历史问题归档

2. **技术方案核心**:
   - **问题**: OpenClaw native browser 插件 schema 限制（无法自定义 executablePath、--no-sandbox）
   - **方案**: systemd 常驻服务 + agent-browser CDP 连接 + batch 模式
   - **优势**: 绕过插件配置限制，避免 exec timeout，多代理共享 Chromium 实例

3. **架构设计**:
   ```bash
   OpenClaw Agent
          ↓ exec
   browser-stable.sh (wrapper)
          ↓ --cdp 9223
   chromium-cdp.service (常驻 Chromium)
   ```

4. **关键配置**:
   - 端口: 9223 (CDP)
   - 启动参数: --headless --no-sandbox --disable-setuid-sandbox
   - 内存限制: 500M
   - 服务: systemctl status chromium-cdp

5. **使用方式**:
   - 直接调用: `/root/.openclaw/share/browser/browser-stable.sh`
   - 软链接: `ln -s ~/.openclaw/workspace-xxx/browser`
   - 支持命令: open/url/snapshot/screenshot/ping

6. **适用场景**:
   - ✅ 自动化截图、页面解析（优化场景）
   - ✅ 数据提取（磁力链接、商品信息）
   - ⚠️  需要登录状态的复杂交互（需配置 --user-data-dir）
   - ❌ 高频访问（>10次/分钟）考虑代理轮换

**学习收获**:
- 理解了 OpenClaw browser 工具的限制根因（root 沙盒、schema 不可定制）
- 掌握了 systemd 服务化管理浏览器的成熟方案
n- 获得了稳定、可复现的浏览器自动化路径
- 该方案适用于所有 OpenClaw agent，通过共享目录协作

## 12:23 - 深入学习"截图转链接"方法并验证

**用户要求**: "截图转链接经验学会了吧"

**核心技术拆解**:

1. **snapshot → 获取 ref**
   - 快照输出可访问性树，每个元素有唯一 `ref`（如 e36）
   - 示例: `- link "现货黄金" [ref=e36]`

2. **click → 自动点击**
   - 使用 batch 模式: `echo '[["click","e36"]]' | agent-browser --cdp 9223 batch`
   - 无需知道具体 URL，直接通过 ref 编号点击

3. **eval → 数据提取**
   - 执行 JavaScript: `echo '[["eval","document.body.innerText"]]' | agent-browser --cdp 9223 batch`
   - 可定制脚本来提取特定元素内容

**实际验证**:
- ✅ 打开金投网首页 → snapshot → 提取 "现货黄金" 链接 ref=e36
- ✅ 执行 `click e36` → 页面导航（URL 变为 https://m.cngold.org/quote/gjs/gjhj_xhhj.html?key=au）
- ⚠️  详情页价格数据: snapshot 显示多为弹幕和 Canvas，价格文本不在 DOM 中
- ✅ 使用 `eval` 提取页面文本，确认价格数据可能需要 WebSocket 监听或 Canvas 解析

**"截图转链接"经验总结**:
- **技术要点**: 快照 → 解析 ref → click → 自动导航 → eval 提取
- **适用性**: 普通 HTML 页面（含链接文本）完美可行；Canvas/WebSocket 渲染的数据需额外处理
- **价值**: 无需人工复制 URL，实现全自动化抓取流程

**成果**: 已掌握从截图（快照）中自动识别链接并点击的完整技能链。

## 12:50 - browser 组件使用经验总结

**核心技能**:
- ✅ systemd 服务管理: `chromium-cdp` 常驻运行 (port 9223)
- ✅ wrapper 脚本: `/root/.openclaw/share/browser/browser-stable.sh`
- ✅ 命令集: open/url/snapshot/screenshot/ping

**关键认知**:
1. **snapshot 输出 ref 编号仅用于 agent-browser 内部识别**，真实 DOM 操作仍需 `eval` + `querySelector`
2. **点击链接的正确流程**:
   - snapshot → 提取链接文本 → eval 查找真实 `href` → 直接 open
   - ❌ 不要尝试 `click eXX`（ref 编号不可用于 batch click）
3. **截图转链接**:
   - 本地文件 → Python HTTP 服务 → 本机 IP + 端口 → 可点击 URL
   - 格式: `http://192.168.1.xxx:8000/文件名`
4. **多代理协作**: 直接使用共享路径 `/root/.openclaw/share/browser/`，无需软链接
5. **等待策略**: open 后需 `sleep` 或 `wait --load networkidle` 确保页面加载

**应用场景验证**:
- ✅ 金投网首页 → 提取"现货黄金"链接 → 打开详情页
- ✅ 沪金期货页 → 截图 → HTTP 服务 → 生成可点击链接

**注意事项**:
- ⚠️  动态加载页面（WebSocket/Canvas）可能需要更复杂的数据提取策略
- ⚠️  截图大小差异: 等待不充分会导致文件极小（2KB vs 158KB）

**下一步优化**:
