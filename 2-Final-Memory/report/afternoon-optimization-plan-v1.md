## 一、现状诊断

基于 5/28 午盘报告（afternoon-analysis-2026-05-28.md，250行）的实际生成情况：

| # | 问题 | 影响 | 根因 |
|---|------|------|------|
| **P1** | **生成时间长** | 12:07 触发 → 12:15 完成，耗时 ~8 分钟，cron 超时阈值 8 分钟 | ① SKILL.md 执行流程串行：Step 1 采集 → Step 2 读上下文 → Step 3 分4步生成 → Step 4 保存 → Step 5 邮件 → Step 6 清理，每步等上一步完成 ② 读文件次数多：SKILL.md + report-templates.md + checklists.md + portfolio.md + 早盘报告 + context-cache.json，至少6次 read ③ 东方财富 push2 需独立 web_fetch 两次（行业+概念），每次等待网络往返 |

## 二、优化改动（按优先级排序）

### 🔴 改动1：操作指令一体化（可操控性↑↑↑）

**现状问题**：操作指令分散在3个地方，老板需要自己拼凑。

**改动内容**：将"条件核对表"+"持仓表"+"决策树"合并为 **「午间操作指令总表」**，作为报告的第一个数据章节（紧跟条件检查之后）。

**具体做法**：

1. **保留"🔴 第一优先：条件核对表"**，但精简为只列条件变化状态，不重复操作建议
2. **新增"🎯 午间操作指令总表"**，替代原"持仓表现+建议更新"大表 + "午后操作决策树"
3. **删除原"五、持仓表现+建议更新"章节**（信息已合并到指令总表）
4. **删除原"七、午后操作决策树"章节**（三情景合并到指令总表的"执行窗口"列）
5. **删除原"🎯 午后操作决策树"章节标题**

**新模板**：

```markdown
## 🎯 午间操作指令总表
```

**决策树合并规则**：
- 原"情景一：午后继续下跌"的触发条件 → 合并到指令总表末尾的"午后继续下跌预案"一行
- 原"情景二：午后反弹企稳"的操作 → 已体现在指令总表的"执行窗口"列中
- 原"情景三：横盘震荡" → 默认行为就是按指令总表执行，无需单独列出

**预期效果**：老板看一张表就知道该干什么，可操控性大幅提升。删除 ~50行重复内容。

### 🔴 改动2：数据采集并行化（生成时间↓30-60秒）

**现状问题**：Step 1 数据采集串行执行。虽然 collect_report_data.py 内部已用5线程并行，但 SKILL.md 的执行流程是：先跑脚本 → 再 web_fetch 东方财富 → 再搜索热点 → 再读文件，每一步等上一步完成。

**改动内容**：将 SKILL.md 的 Step 1 改为**全并行采集**，所有数据源同时发起，全部完成后统一进入 Step A。

**具体做法**：

**当前流程（串行）**：
```
Step 1a: 运行 collect_report_data.py（~1秒，内部5线程并行）
  → 等待完成
Step 1b: web_fetch 东方财富行业板块资金流向（~5秒）
  → 等待完成
Step 1c: web_fetch 东方财富概念板块资金流向（~5秒）
  → 等待完成
Step 1d: tavily_search 上午市场热点（~10秒）
  → 等待完成
Step 1e: read 早盘报告全文（~2秒）
  → 等待完成
Step 1f: read portfolio.md（~1秒）
  → 等待完成
总耗时：~24秒
```

**优化流程（并行）**：
```
Step 1: 同时发起所有采集（不等结果）
  线程A: python3 collect_report_data.py --type afternoon --cache ...
  线程B: web_fetch 东方财富行业板块资金流向
  线程C: web_fetch 东方财富概念板块资金流向
  线程D: tavily_search 上午市场热点
  线程E: read 早盘报告全文（read工具）
  线程F: read portfolio.md（read工具）
  → 等待全部完成（最长等待60秒）
总耗时：~10秒（由最慢的搜索决定）
```

**SKILL.md Step 1 模板修改**：
```markdown
### Step 1: 数据采集（全部并行，不等结果）

同时发起以下采集，全部完成后统一进入 Step A：

1. **脚本采集**（并行）：
   `python3 $SCRIPT --type afternoon --output /tmp/afternoon_data.json --cache "/tmp/report_data_afternoon_$(date +%Y%m%d).json"`

2. **东方财富 push2**（并行，两次 web_fetch 同时发起）：
   - 行业板块资金流向：`web_fetch "https://push2.eastmoney.com/api/qt/clist/get?pn=1&pz=10&po=1&np=1&fltt=2&invt=2&fid=f62&fs=m:90+t:2&fields=f2,f3,f4,f6,f12,f14,f62" maxChars=5000`
   - 概念板块资金流向：`web_fetch "https://push2.eastmoney.com/api/qt/clist/get?pn=1&pz=15&po=1&np=1&fltt=2&invt=2&fid=f62&fs=m:90+t:3&fields=f2,f3,f4,f6,f12,f14,f62" maxChars=8000`

3. **资讯搜索**（并行）：
   `tavily_search "A股 上午 市场热点 [日期]" max_results=5`

4. **读取上下文**（并行）：
   - read 早盘报告全文
   - read portfolio.md
   - read context-cache.json（如果存在）

⚠️ 注意：以上6项采集同时发起，不要等前一个完成再发起下一个。
    全部完成后，汇总数据到 /tmp/afternoon_data_merged.json，再进入 Step A。
```

**东方财富 push2 合并优化**（可选，P2）：
当前行业板块用 `fs=m:90+t:2`，概念板块用 `fs=m:90+t:3`，是两个独立请求。可以尝试合并为一个请求 `fs=m:90+t:2,3`，但需要测试返回格式是否兼容。**暂不执行，作为预留优化**。

**预期效果**：数据采集从 ~24秒 降至 ~10秒，节省 ~14秒。

**改动内容**：将"二、🌍 外资动向 + 资金流向深度分析"合并为 **「二、💰 资金流向深度分析」**，去掉外资全景空表。

**具体做法**：

- ❌ 外资全景表（融资融券/深股通/MSCI中国/富时罗素 4行全为"—"）

### 🟡 改动4：新基金推荐章节条件化（质量↑）

**现状问题**：新基金推荐成为"鸡肋"章节——每次都留完整章节骨架，但经常写"本期无新增推荐"。5/28 午盘报告中该章节 ~20行，实际有效信息只有3句话。

**改动内容**：新基金推荐章节根据内容多少自适应展开/折叠。

**具体规则**：

| 情况 | 章节标题 | 内容量 | 格式 |
|------|---------|--------|------|
| 有新增推荐（≥1只） | 八、🆕 新基金建仓推荐更新 | 完整（表格+API验证+7天预判） | 完整模板 |
| 只验证早盘推荐 | 八、🆕 早盘推荐验证 | 简化（一段话+验证表格） | 简化模板 |
| 无推荐且无需验证 | 八、🆕 早盘推荐跟踪 | 极简（一句话） | 极简模板 |

**简化模板（只验证）**：
```markdown
## 八、🆕 早盘推荐验证

早盘推荐的电力ETF联接C(016186)和红利ETF联接C(012762)得到上午资金流向验证：

| 基金 | 早盘预判 | 上午验证 | 结论 |
|------|---------|---------|------|
| 电力ETF联接C(016186) | 主力资金持续流入 | 电力板块+14.96亿，继续TOP3 | ✅ 验证通过 |
| 红利ETF联接C(012762) | 防御价值 | 市场震荡，红利策略有效 | ✅ 验证通过 |

MLCC/被动元件概念爆发但属于短期事件催化，7天持有期不确定性大，不推荐追高。
```

**极简模板（无内容）**：
```markdown
## 八、🆕 早盘推荐跟踪

本期无新信号，早盘推荐的电力(016186)+红利(012762)继续持有观察，7天持有期预判不变。
```

**预期效果**：无推荐时节省 ~15行，有推荐时保持完整。报告不再有"凑数"章节。

### 🟡 改动5：早盘要素变化对比灵活化（质量↑）

**现状问题**：模板固定5个要素（上证/科创50/创业板/资金面/核心事件），但实际市场变化更复杂。5/28 午盘报告实际需要对比8个要素（上证/科创50/创业板/资金面/核心事件/外资动向/科创AI风险/半导体材料风险），但模板只有5行，导致后3个被挤进"校准结论"文字中。

**改动内容**：将固定5要素改为动态要素表，根据当日实际情况灵活增减。

**具体做法**：

**删除固定5要素约束**，改为：

```markdown
## 四、🔄 早盘预判 vs 午间实际

> 要素数量根据当日实际情况灵活增减，重点包含：指数预判、资金面、核心事件、关键持仓触发状态

| 要素 | 早盘预判 | 午间实际 | 校准 |
|------|---------|---------|------|
| 上证指数 | 4080-4105(基准) | 4087.86(-0.14%) | ✅命中 |
| 科创50 | 1810-1840(基准) | 1838.84(+1.29%) | ✅命中上限 |
| ... | ... | ... | ... |

**预判校准结论**：[2-3句话总结]
```

**最低要求**：至少包含4个要素（上证/科创50/资金面/核心事件），不设上限。

**预期效果**：避免要素遗漏或强行凑数，报告更准确地反映当日实际变化。

### 🟢 改动7：风险提示自适应（质量↑，预留）

**现状问题**：风险提示固定"市场风险+个股风险+流动性风险"三段，有时没有流动性风险也硬凑。

**改动内容**：风险提示改为自适应，有则写，无则一句话带过。

```markdown
## 七、⚠️ 风险提示更新

1. [市场风险，有则写]
2. [个股/板块风险，有则写]
```

**预期效果**：避免凑数，报告更精炼。
