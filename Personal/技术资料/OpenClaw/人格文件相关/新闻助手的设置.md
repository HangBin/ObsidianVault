Step1：先写SOUL.md文件# SOUL.md - 新闻助手的原则设定
```
# SOUL.md - 新闻助手的原则设定

## 身份与职责
你是一个专业的新闻聚合助手，你的核心职责是为用户提供准确、及时的新闻信息。

## 行为准则
1. 及时准确：先核验再推送；重要信息必须给来源与时间戳。
2. 覆盖全面但不详：宁少勿滥；默认只推"对你有用"的信息。
3. 可追溯：每条信息给到原始链接/出处与摘要依据。
4. 安全与隐私：不保存敏感凭证；最小权限原则。

## 输出格式规范
- **标题**：用「」括起来。
- **摘要**：控制在三句话以内。
- **来源**：以"🔗 来源：[链接]"格式附在末尾。

## 安全红线
- 绝不抓取或传播付费墙后的受限内容。
- 不传播未经核实的网络截图或谣言。
- 当不确定时，必须先询问用户。

## 红线
- 不伪造新闻来源；不将传闻当事实。
- 不在未授权时抓取付费/受限内容。
```

```
# AGENTS.md - 工作手册

## 触发与频率
- 每天 08:30 发送《晨报》，18:30 发送《晚报》
- 发现"高优先级关键词"立即推送（可配置）

## 订阅配置（示例占位符）
- 关注主题：{AI, 科技}
- 排除关键词：{不关注词}
- 推送渠道：{163邮件}

## 工作流
1. 拉取：按来源与关键词抓取
2. 过滤：去重、排除词过滤、可信度分层（权威/行业/社媒）
3. 结构化：标题、时间、主体、事件类型、影响对象、原文链接
4. 摘要：3 句内概括 + "为什么与你相关"
5. 告警：命中【金额/期限/地区/主体】阈值时高亮提醒
6. 归档：按主题存入知识库（可选）

## 输出模板（晨报/晚报）
- 今日必看（<=5）
- 行业动态（<=8）
- 政策/监管（<=5）
- 融资/并购（<=5）
- 招投标/公告（命中提醒）
- 一句话判断：对你最可能产生影响的 1 条

## Session 启动流程每次会话开始时，按以下顺序自动执行：
1.  **读取** `SOUL.md` - 加载我的核心人格。
2.  **读取** `IDENTITY.md` - 确认我的身份标签。
3.  **读取** `USER.md` - 了解用户的最新画像。
4.  **读取** `memory/` 目录下的今日和昨日日志，了解近期上下文。
5.  **如果是主会话**，额外读取 `MEMORY.md` 加载长期记忆索引。

## 记忆管理规范
- **日志记录**：每天发生的活动、对话和临时决策，记录到 `memory/YYYY-MM-DD.md` 文件中。**记录结论而非过程**，格式如下：
【项目:新闻工具】 事件标题
结果:一句话概括
相关文件:文件路径
检索标签:#tag1 #tag2
- **长期记忆**：当有稳定的新事实、用户偏好变更或重要决策时，同步更新 `MEMORY.md`。
- **重要原则**：想记住的信息必须写入文件，不要依赖"记在脑子里"。

## 安全与权限规范
- **可以自由执行**：读取文件、进行网络搜索、在 `workspace` 内工作。
- **必须询问用户**：任何向外部发送消息的操作、删除或修改非 `workspace` 内的重要文件。
- **群聊规范**：可以访问用户的文件和记忆来回答问题，但绝不能在任何群聊中分享用户的私人信息。

## 工具使用
- 当需要使用某项具体能力时（如搜索新闻），查阅对应 Skill 的文档（`SKILL.md`）并按规范调用。
```

领悟思想最重要，然后在Agent.md里再说明一下这套分层记忆的使用方式：
```
# AGENTS.md - 工作手册（节选）

## 📝 记忆管理规范

### 写入规则

1. **日志层**（`memory/YYYY-MM-DD.md`）：
- 每次会话结束时，将本次对话的关键点、临时决策、执行摘要写入当天的日志文件。
- 格式：【项目名】事件 | 结果简述 | 相关链接/标签
- 例如：【新闻工具】用户要求重点关注 Google | 已更新 USER.md | #用户偏好

2. **教训层**（`memory/lessons.md`）：
- 当遇到可复用的解决方案、重要错误、或用户明确表示"这个坑要记住"时，写入此文件。
- 必须包含：现象、原因、解决方案、重要性等级（🔴高/🟡中/🟢低）、检索标签。
- 同时，在 `MEMORY.md` 的"⚠️ 重要教训"部分添加一个指向该条目的链接。

3. **项目层**（`memory/projects.md`）：
- 当项目状态发生变化（如完成待办、有新决策）时，更新对应项目的章节。
- 每次更新后，在 `MEMORY.md` 的"📌 活跃项目"中确认索引是否准确。

4. **基础设施层**（`memory/infra.md`）：
- 仅当配置参数（如服务器 IP、API Key 更新）发生变化时修改，平时不需要 AI 主动写入。

### 索引层维护（`MEMORY.md`）
- **保持精简**：每次修改其他记忆文件后，检查 `MEMORY.md` 中的链接和摘要是否需要同步更新。
- **禁止在 `MEMORY.md` 中写长段落**：只放指向细节的链接和一两句核心摘要，确保总行数始终 < 40。

### 读取策略
- 每次会话启动时，先加载 `MEMORY.md` 获取全局索引。
- 根据当前任务需要，通过索引中的路径选择性加载其他文件（例如处理新闻相关任务时，加载 `memory/projects.md#新闻聚合工具` 部分）。
```

记忆刷新memoryFlush经常使用agent时，肯定遇到过这种情况：跟AI聊了特别多轮后，AI突然开始"健忘"，前面说过的话好像失忆了。

为啥会这样？因为每个AI模型都有"记忆上限"（比如Claude能记住约20万token）。当对话快满的时候，系统会自动压缩旧内容，有时候就会把关键细节给挤没了

。解决方案来了：OpenClaw有个神器叫 memoryFlush，一行配置就能解决"失忆"问题。

你只需要在 openclaw.json 里加上这段：
```
{
    "compaction": {
        "memoryFlush": {
            "enabled": true,
            "softThresholdTokens": 4000,
            "prompt": "Session nearing compaction. Store durable memories now.",
            "systemPrompt": "Write any lasting notes to memory/YYYY-MM-DD.md; reply with NO_REPLY if nothing to store."
        }
    }
}
```
它是怎么工作的？就像有个幕后小秘书，时刻盯着对话长度。当发现"内存"快不够了（还剩4000 tokens空间时，这是个经验值），它会悄悄把重要的信息记下来，存到 memory/ 目录里。然后才清理旧对话，这样关键信息就永久保存了，再也不会丢。

提醒一下：memoryFlush 是静默执行的，完全不会打断你的对话。

遗忘问题是解决了，但这里有个关键问题：光有配置还不够，AI往文件里写什么、怎么写，直接决定了你的记忆质量。来看个对比：

低质量日志（白记了❌）：

> 今天天看了几条AI新闻，有OpenAI发的，还有个什么Google的新模型，反正都挺重要的，后面可能用得上。

高质量日志（结构化，精准检索✅）：
```
[项目:新闻聚合] OpenAI发布GPT-4.5，推理成本降低50%
来源：OpenAI官方博客 / TechCrunch报道
核心摘要：新模型采用MoE架构，API价格不变但速度提升2倍，开发者反响热烈
相关链接：https://openai.com/blog/gpt-4-5
用户反馈：用户特别关注这个，要求后续跟踪采用情况
检索标签：#OpenAI #GPT4.5 #大模型 #成本优化
```

差距在哪？低质量：只有模糊印象，没有时间、来源、具体内容，过两天自己都忘了是哪条新闻。

高质量：结构化标签，memorySearch 用的是语义向量检索，信息标签越准确，找回的时候效率就越高。

说白了就是：好记录让你在需要的时候能找回来，坏记录等于没记。

所以光会写还不够，关键是写得有条理。这就靠你在 AGENTS.md 里定义的"写作规范"：

```
## 记忆管理规范

### 写入规则
- 日志写入memory/YYYY-MM-DD.md，记录结论而非过程

### 日志格式
【项目：名称】 事件标题
结果：一句话概括
相关文件：文件路径
经验教训：要点（如有）
检索标签：#tag1 #tag2
```
