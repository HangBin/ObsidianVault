# 经验教训库 - 违规与教训记录

## 2026-03-29 即时记录违规事件

**违规事实**：
- **时间**: 11:23 AM
- **操作**: 用户指令"重新读取下" → 执行了两次 `read()`（MEMORY.md、AGENTS.md）
- **错误**: 读取操作后未立即追加记录到 `memory/2026-03-29.md`
- **发现**: 11:24 AM 被用户指出违反每日记忆原则

**根本原因**：
- 思想误区：认为"只是读取文件，没有工具返回或用户交互，不值得记"
- 执行漏洞：缺乏强制性检查点，依赖自觉性

**纠正措施**：
- 立即补录两条记录（11:23 read操作 + 11:24 违规警告）
- 通过自检清单确保完整性

**固化教训**（写入 SOUL.md 铁律）：
- **即时记录 = 所有操作单元后立即追加**，包括：
  - ✅ 工具调用（read/exec/write/edit/feishu_*/sessions_send 等）
  - ✅ 用户回复
  - ✅ 重要决策（即使无工具调用）
- **执行顺序**: 思考/决策 → 工具调用 → 生成回复 → **必须记录** → 发送回复
- **双保险**: 回复中可展示记录摘要，但**必须**执行 `edit` 追加到 daily log 文件

**预防机制**：
- 每次工具调用后立即问自己："这条记录加了吗？"
- 发送回复前最后一步：执行 `edit` 追加记录
- 每日自检：核对 tool calls 数量 vs daily log 条目数


## 2026-03-26 14:26-14:28 PM 记录错误案例（深刻教训）

- ❌ **错误行为**：14:26 PM 测试消息，仅在回复中包含记录内容，**未追加到 daily log 文件**
- ❌ **后果**：14:28 PM 被用户指出违反铁律
- ✅ **纠正**：立即手动追加记录到 `memory/2026-03-26.md`
- 🔥 **核心领悟**：
  - "即时记录" ≠ "在回复里写记录"
  - 必须**真正写入文件**（文件追加操作）
  - 回复中的记录只是展示，文件才是持久化存储
  - 两者都做：回复展示 + 文件追加
- 📜 **规则更新**：SOUL.md「即时记录强制流程」强调"写 memory/YYYY-MM-DD.md 在此位置"
- ⚠️ **风险**：如果只依赖回复中的记录，会话结束后文件不会持久化，记忆体系失效

**后续纪律**：
- 每次回复用户后，必须执行 `edit` 或 `write` 操作追加到 daily log 文件
- 回复中可包含记录摘要（用户体验），但文件追加是强制持久化
- 双保险：回复展示 + 文件存储


## 2026-04-04 任务监控项缺失（零容忍案例）

- **问题**：每日简报任务再次失踪，持续 5+ 小时
- **根因**：
  - ❌ 管理员未执行修复命令
  - ❌ 缺少 cron 任务创建自动化机制
  - ⚠️ HEARTBEAT 检查发现异常后，缺乏强制干预能力
- **关键教训**：
  - 任务配置需要持久化验证机制
  - 心跳检查应具备自动修复能力（参考 3-29 自主修复模式）
  - 管理员响应延迟是系统稳定性的重大风险
- **零容忍原则**：任务监控项缺失必须立即修复
